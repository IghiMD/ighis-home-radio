# Contributing to Ighi's Home Radio

🎵 Thank you for your interest in contributing to Ighi's Home Radio! We welcome contributions from the community.

## 🚀 Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/YOUR_USERNAME/ighis-home-radio.git`
3. Create a new branch: `git checkout -b feature/your-feature-name`
4. Make your changes
5. Test your changes thoroughly
6. Commit your changes: `git commit -m "Add: your feature description"`
7. Push to your fork: `git push origin feature/your-feature-name`
8. Create a Pull Request

## 📋 Guidelines

### Code Style
- Use consistent indentation (4 spaces for PHP, 2 spaces for HTML/CSS/JS)
- Follow PSR-12 coding standards for PHP
- Use meaningful variable and function names
- Comment your code where necessary
- Keep functions small and focused

### Commit Messages
Use clear and descriptive commit messages:
- `Add: new feature description`
- `Fix: bug description`
- `Update: what was updated`
- `Remove: what was removed`
- `Refactor: what was refactored`

### Testing
- Test your changes on different browsers
- Ensure mobile responsiveness
- Check console for errors
- Test with and without API keys

### Documentation
- Update README.md if needed
- Document new features
- Include examples where helpful
- Update .env.example for new variables

## 🐛 Reporting Issues

1. Check if the issue already exists
2. Use the issue template
3. Provide clear description
4. Include steps to reproduce
5. Add screenshots if relevant
6. Mention your environment (browser, PHP version, etc.)

## 💡 Suggesting Features

1. Check if already suggested
2. Open a new issue with "Feature Request" label
3. Describe the feature clearly
4. Explain why it would be useful
5. Provide examples if possible

## 🔒 Security

If you find a security vulnerability:
- Do NOT open a public issue
- Email us at: security@ighishomeradio.com
- We'll respond within 48 hours

## 📝 Pull Request Process

1. Ensure your PR description clearly describes the problem and solution
2. Reference any related issues
3. Update documentation if needed
4. Ensure all tests pass
5. Request review from maintainers
6. Be responsive to feedback

## 🎨 UI/UX Contributions

- Maintain the existing design language
- Ensure accessibility (WCAG 2.1 AA)
- Test on multiple screen sizes
- Optimize images and assets
- Keep animations smooth and purposeful

## 🌐 Translation Guidelines

When adding new languages:
1. Add to `translations` object in index.html
2. Create language switcher button
3. Translate all UI elements
4. Test thoroughly
5. Update documentation

## 📜 Code of Conduct

- Be respectful and inclusive
- Welcome newcomers
- Focus on constructive criticism
- No harassment or discrimination
- Keep discussions professional

## 🙏 Recognition

Contributors will be:
- Listed in README.md
- Mentioned in release notes
- Thanked on our social media
